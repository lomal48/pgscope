# Серверы и Инспектор

Эта страница описывает два представления всего парка: список «Серверы» с карточкой каждого сервера и «Инспектор» — сводные таблицы, в которых серверы и базы удобно сравнивать между собой. Оба строятся по сводке, которую pgscope пересчитывает при каждом новом отчёте сервера.

## Страница «Серверы» {#servers}

Страница «Серверы» открывается по адресу `#/` и пунктом «Серверы» в боковом меню. В заголовке — число серверов под мониторингом, ниже — карточки серверов.

В список попадают:

- серверы, владельцем которых вы являетесь, — они создаются автоматически при первом отчёте с новым именем сервера (имя задаётся в команде отправки, см. [Отправка отчётов](collect.md));
- серверы, к которым вам открыли доступ, — у них есть метка «общий» (см. [Команда, профиль и аккаунт](teams.md)).

Сервер идентифицируется сочетанием владельца, типа (PostgreSQL или Pgpool) и имени. Если отправить отчёт под другим именем, появится новый сервер, а не обновится существующий.

Список упорядочен по типу сервера (сначала Pgpool, затем PostgreSQL) и по имени. Интерфейс перечитывает его раз в минуту, поэтому новые значения на карточках появляются не позже чем через минуту после прихода отчёта. Щелчок по карточке открывает «Обзор» сервера (для Pgpool — панель Pgpool).

### Карточка сервера PostgreSQL {#postgres-card}

| Элемент | Что показывает |
|---|---|
| имя и метка «общий» | имя сервера из команды отправки; «общий» — сервер принадлежит другому пользователю и открыт вам |
| строка версии | `PostgreSQL` и значение `server_version`; добавка «реплика» — сервер находится в режиме восстановления (standby) |
| значок оповещений | число сработавших оповещений по уровням или «Норма» (см. [Значок оповещений](#alert-badge)) |
| «Бэкенды» | число клиентских подключений из отчёта и `max_connections` в виде `N/M` |
| «Размер» | суммарный размер всех баз сервера |
| «Попадания в кеш» | доля чтений блоков, обслуженных из `shared_buffers`, по всем базам с момента сброса статистики; ниже 90 % значение выделяется жёлтым |
| «Отчёт» | сколько времени прошло с последнего отчёта; жёлтым — если больше 15 минут или отчётов не было |
| метки PgBouncer | имена экземпляров PgBouncer, которые присылали отчёты для этого сервера (см. [PgBouncer](integrations.md#pgbouncer)) |

### Карточка Pgpool {#pgpool-card}

| Элемент | Что показывает |
|---|---|
| строка версии | `Pgpool` и версия Pgpool-II |
| «Бэкенды в работе» | число узлов в состоянии `up` или `waiting` из общего числа узлов; если работают не все, значение выделяется жёлтым |
| «Попадания в кеш» | доля попаданий в кеш запросов Pgpool (query cache) |
| «Отчёт» | время с последнего отчёта (без выделения цветом) |

Подробности о Pgpool — в разделе [Pgpool](integrations.md#pgpool).

### Значок оповещений {#alert-badge}

Справа вверху карточки — сводка сработавших [правил оповещений](alerts.md):

| Значок | Значение |
|---|---|
| красный с числом | сколько сработало оповещений уровня «Критично» |
| жёлтый с числом | сколько сработало оповещений уровня «Предупреждение» |
| зелёный «Норма» | сработавших оповещений нет |

Считаются не правила, а сработавшие записи: одно правило, под которое попало несколько объектов (например, пять таблиц с раздуванием), даёт пять записей. Правила проверяются при каждом новом отчёте PostgreSQL и сразу после добавления или удаления правила.

> [!NOTE]
> Значок отражает только правила оповещений. Проблемы, которые находит [диагностика](monitoring.md#diagnostics), на значок не влияют. Для серверов Pgpool правила оповещений в интерфейсе не настраиваются, поэтому их карточка всегда показывает «Норма».

### Устаревшие отчёты {#stale}

Если с последнего отчёта прошло больше 15 минут, значение «Отчёт» на карточке PostgreSQL становится жёлтым, а на страницах сервера жёлтой становится точка свежести в верхней панели (см. [Свежесть отчёта](ui.md#freshness)). Все показатели карточки при этом остаются такими, какими были в последнем отчёте.

Что проверить:

1. Работает ли задание cron, systemd-таймер или агент, который отправляет отчёты (см. [Отправка отчётов](collect.md) и [Docker и Docker Swarm](docker.md#troubleshooting)).
2. Что отвечает pgscope на отправку — коды ответов описаны в разделе [Ответы сервера](collect.md#responses).
3. Не переименован ли сервер в команде отправки: отчёты под новым именем создают новый сервер, а старая карточка остаётся с устаревшими данными.

Ненужный сервер владелец может удалить кнопкой «Удалить сервер» на странице «Команда и настройки» (см. [Команда и настройки](teams.md#server-settings)). Если отчёты под этим именем продолжат приходить, сервер появится снова.

### Пустой список {#empty}

Пока отчётов нет, вместо карточек показывается «Серверов пока нет» и готовая команда для первого отчёта с вашим API-ключом и адресом pgscope из `PGSCOPE_BASE_URL` (если у вашей учётной записи есть API-ключ; у учётных записей участников команды его нет). Другие варианты подключения — PgBouncer, Pgpool, планы запросов, AWS RDS — приведены на странице «Профиль» (см. [Профиль](teams.md#profile)).

```bash
pgmetrics --no-password -f json -h DBHOST -U DBUSER db1 db2 \
  | pgdash -a APIKEY --base-url=http://monitor:8080/api/v1 report my-server
```

## Инспектор {#inspector}

«Инспектор» (адрес `#/inspector`) собирает ключевые показатели всех серверов в пять таблиц. Он нужен, чтобы сравнивать серверы между собой и быстро находить худшие: самый высокий возраст XID, самое большое отставание реплики, меньше всего свободного места.

Особенности:

- В «Инспекторе» участвуют только серверы PostgreSQL, от которых уже пришёл хотя бы один отчёт. Серверы Pgpool не показываются.
- Значения берутся из последнего отчёта каждого сервера. Если сервер перестал присылать отчёты, его строка показывает устаревшие данные — следите за столбцом «Последний отчёт» на вкладке «Серверы».
- Все таблицы сортируются щелчком по заголовку (см. [Таблицы](ui.md#tables)); щелчок по строке открывает соответствующую страницу сервера.
- Цветом выделяются значения выше порогов: жёлтым — предупреждение, красным — критично. Пороги приведены в таблицах ниже. Это подсказки, а не оповещения.

### Вкладка «Серверы» {#inspector-servers}

Одна строка на сервер. По умолчанию сортировка по имени; поле «Фильтр…» ищет по имени сервера. Щелчок по строке открывает «Обзор» сервера.

| Столбец | Что показывает | Выделение |
|---|---|---|
| «Сервер» | имя сервера | — |
| «Версия» | значение `server_version` | — |
| «Роль» | «ведущий» (primary) или «реплика» (standby) | — |
| «Время работы» | сколько времени прошло с запуска PostgreSQL | — |
| «Бэкенды» | клиентские подключения / `max_connections`; сортируется по доле занятых подключений | жёлтым больше 75 %, красным больше 90 % |
| «Ожидают» | бэкенды, ожидающие блокировку (`wait_event_type = Lock`) | жёлтым больше 0 |
| «Простой в транзакции» | бэкенды в состоянии `idle in transaction` | жёлтым больше 0 |
| «Размер» | суммарный размер баз | — |
| «Попадания в кеш» | доля попаданий в `shared_buffers` по всем базам с момента сброса статистики | жёлтым ниже 95 %, красным ниже 80 % |
| «Доля фиксаций» | доля зафиксированных транзакций среди всех завершённых (commit / (commit + rollback)) | — |
| «Оповещения» | число сработавших оповещений | красным, если есть критичные, иначе жёлтым |
| «Последний отчёт» | время с последнего отчёта | жёлтым больше 15 минут |

### Вкладка «Базы данных» {#inspector-databases}

Все базы всех серверов в одной таблице. По умолчанию сортировка по размеру (сначала самые большие); «Фильтр…» ищет по имени сервера и базы. Щелчок по строке открывает страницу базы (см. [Базы данных](objects.md#databases)).

| Столбец | Что показывает | Выделение |
|---|---|---|
| «Сервер», «База данных» | где находится база | — |
| «Размер» | размер базы | — |
| «Бэкенды» | подключения к базе (`numbackends`) | — |
| «Попадания в кеш» | доля попаданий в кеш по базе с момента сброса статистики | жёлтым ниже 95 %, красным ниже 80 % |
| «Доля фиксаций» | доля фиксаций среди завершённых транзакций базы | жёлтым ниже 90 % |
| «Возраст XID / лимит заморозки» | `age(datfrozenxid)` в процентах от `autovacuum_freeze_max_age` | жёлтым больше 100 %, красным больше 150 % |
| «Взаимоблокировки» | счётчик взаимоблокировок с момента сброса статистики | — |
| «Временные файлы» | объём, записанный во временные файлы с момента сброса статистики | — |

Значение «Возраст XID / лимит заморозки» больше 100 % означает, что для базы уже должен работать агрессивный autovacuum против переполнения счётчика транзакций. Если значение продолжает расти, autovacuum не успевает — см. [Очистка (vacuum)](server.md#vacuum).

### Вкладка «Репликация» {#inspector-replication}

По умолчанию сортировка по отставанию (сначала наибольшее). Щелчок по строке открывает страницу «Репликация» сервера (см. [Репликация](server.md#replication)).

| Столбец | Что показывает | Выделение |
|---|---|---|
| «Роль» | «ведущий» или «реплика» | — |
| «Реплики» | число подключённых получателей WAL (строк `pg_stat_replication`) | — |
| «Макс. отставание» | на ведущем — максимальное отставание реплик в байтах (текущий LSN минус `replay_lsn`); на реплике — объём полученного, но ещё не воспроизведённого WAL, а если у неё есть свои каскадные реплики — наибольшее из этих значений; «—», если репликация есть, но ни одно отставание неизвестно (PostgreSQL не сообщил нужную позицию WAL, например у `pg_basebackup` или у реплики без приёмника WAL) | жёлтым больше 64 МиБ, красным больше 1 ГиБ |
| «Макс. отставание по времени» | на ведущем — максимальный `replay_lag`; на реплике — время с момента воспроизведения последней транзакции | — |
| «Неактивные слоты» | слоты репликации, к которым сейчас никто не подключён | жёлтым больше 0 |

> [!TIP]
> На реплике «Макс. отставание по времени» растёт и тогда, когда ведущий просто не выполняет транзакций: новых транзакций для воспроизведения нет. Оценивайте его вместе с отставанием в байтах.

### Вкладка «Идентификаторы транзакций» {#inspector-xid}

Вкладка для оценки риска переполнения счётчика транзакций (wraparound). По умолчанию сортировка по использованной доле диапазона (сначала наибольшая). Щелчок по строке открывает страницу «Очистка (vacuum)» сервера.

| Столбец | Что показывает | Выделение |
|---|---|---|
| «Использовано диапазона XID» | (следующий XID − самый старый XID) / 2 147 483 647, с полосой; разность считается по модулю 2³², как в PostgreSQL, поэтому остаётся верной и после того, как счётчик транзакций кластера перейдёт отметку 2³² | полоса зелёная до 40 %, жёлтая больше 40 %, красная больше 75 % |
| «Самая старая база (% от freeze_max_age)» | наибольший по базам сервера `age(datfrozenxid)` в процентах от `autovacuum_freeze_max_age` | — |
| «Долгие транзакции» | бэкенды, у которых транзакция открыта дольше 5 минут | жёлтым больше 0 |

Долгие транзакции мешают заморозке строк и удержанию счётчика в безопасных пределах, поэтому они показаны рядом.

### Вкладка «Диск и WAL» {#inspector-disk}

По умолчанию сортировка по свободному месту (сначала наименьшее). Серверы без данных о дисках («н/д») при любом направлении сортировки оказываются в конце списка, после серверов с реальными значениями. Щелчок по строке открывает страницу «WAL и контрольные точки» сервера (см. [WAL](server.md#wal)).

| Столбец | Что показывает | Выделение |
|---|---|---|
| «Мин. свободно на диске» | наименьшая доля свободного места среди дисков с табличными пространствами; «н/д», если pgmetrics не передал данные о дисках | жёлтым ниже 20 %, красным ниже 10 % |
| «Файлы WAL» | число файлов в `pg_wal` | — |
| «Готовы к архивации» | файлы WAL, готовые к архивации, но ещё не заархивированные | жёлтым больше 10 |
| «Архивация» | «сбой», если последняя попытка архивации завершилась ошибкой позже последней успешной, иначе «норма» | «сбой» красным |
| «Средняя нагрузка» | load average за 1 минуту; «н/д» без системных метрик; нулевая нагрузка показывается числом | — |
| «Использовано памяти» | занятая память в процентах от общей (занято + свободно + буферы + кеш); «н/д» без системных метрик | — |

Данные о дисках, нагрузке и памяти есть только тогда, когда pgmetrics собирает системные метрики: он делает это, если работает на том же хосте Linux, что и PostgreSQL (подключение через Unix-сокет или локальный адрес). При запуске pgmetrics с другой машины эти столбцы показывают «н/д» (см. [Система](server.md#system)).

## Сценарии сравнения парка {#use-cases}

| Задача | Где смотреть |
|---|---|
| Какие серверы близки к пределу подключений | вкладка «Серверы», сортировка по «Бэкенды» (по доле занятых подключений) |
| Какие серверы перестали присылать отчёты | вкладка «Серверы», сортировка по «Последний отчёт» по возрастанию (второй щелчок по заголовку) |
| Где хуже всего кешируется чтение | вкладка «Серверы» или «Базы данных», сортировка по «Попадания в кеш» по возрастанию |
| Где выше всего риск wraparound | вкладка «Идентификаторы транзакций», затем вкладка «Базы данных» с сортировкой по «Возраст XID / лимит заморозки» |
| Какие реплики отстают | вкладка «Репликация» (сортировка по отставанию уже включена) |
| Где заканчивается место и не работает архивация | вкладка «Диск и WAL»: «Мин. свободно на диске», «Готовы к архивации», «Архивация» |
| Самые большие базы парка и базы с активным использованием временных файлов | вкладка «Базы данных», сортировка по «Размер» или «Временные файлы» |
| Где много откатов | вкладка «Базы данных», сортировка по «Доля фиксаций» по возрастанию |

Выделение цветом в «Инспекторе» — визуальная подсказка. Чтобы узнавать о таких ситуациях без открытия интерфейса, настройте [правила оповещений](alerts.md) с порогами, подходящими вашей нагрузке.
