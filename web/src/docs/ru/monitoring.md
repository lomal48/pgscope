# Обзор, диагностика и AI-чат

Эта страница описывает группу «Мониторинг» сервера PostgreSQL: «Обзор» — главную страницу сервера с ключевыми показателями и графиками, «Диагностику» — автоматическую проверку отчёта на проблемы и ошибки конфигурации, и «AI-чат» — вопросы о сервере на естественном языке.

## Обзор {#overview}

«Обзор» открывается щелчком по карточке сервера на странице «Серверы», выбором сервера в переключателе и пунктом «Обзор» в меню (адрес `#/s/<id>`). В заголовке — полная строка версии PostgreSQL и значок роли: «Ведущий» (primary) или «Реплика» (standby).

Все значения, кроме оповещений, берутся из показываемого отчёта — последнего или выбранного в верхней панели (см. [Выбор прошлого отчёта](ui.md#report-picker)). Если от сервера ещё не пришло ни одного отчёта, вместо страницы показывается «Отчёт ещё не получен».

### Карточки показателей {#overview-stats}

| Карточка | Что показывает | Выделение |
|---|---|---|
| «Версия» | номер версии из `server_version` (без сведений о сборке); ниже — имя хоста, если pgmetrics собрал системные метрики | — |
| «Время работы» | время от запуска PostgreSQL до момента отчёта; ниже — дата запуска | — |
| «Бэкенды» | клиентские подключения / `max_connections`; ниже — доля в процентах | жёлтым больше 75 %, красным больше 90 % |
| «Базы данных» | число баз; ниже — их суммарный размер | — |
| «Попадания в кеш» | доля чтений блоков из `shared_buffers` по всем базам с момента сброса статистики | жёлтым ниже 90 %, иначе зелёным |
| «Оповещения» | число сработавших оповещений или «Нет»; ссылка «открыть оповещения» ведёт на страницу правил | красным при критичных, жёлтым при предупреждениях, зелёным без оповещений |

Как читать:

- **Бэкенды.** Если подключений стабильно больше 75 % от `max_connections`, приложения рискуют получить отказ в подключении при всплеске. Обычное решение — пул подключений (например, PgBouncer), а не увеличение `max_connections`.
- **Попадания в кеш.** Значение накопительное: оно сглаживает недавние изменения. Для типичной OLTP-нагрузки оно обычно 99 % и выше. Значение ниже 90 % говорит о том, что рабочий набор данных не помещается в память или запросы читают много лишних данных. Текущую картину по интервалам показывает график «Попадания в кеш» ниже.

### Кластер {#overview-cluster}

Карточка «Кластер» собирает сведения уровня всего экземпляра PostgreSQL.

| Поле | Что показывает |
|---|---|
| «Системный идентификатор» | идентификатор кластера из управляющего файла; у ведущего и его физических реплик он одинаковый |
| «Линия времени» | номер линии времени (timeline); увеличивается после повышения реплики или восстановления на момент времени |
| «Последняя контрольная точка» | сколько времени прошло от последней контрольной точки до момента отчёта; при наведении — точное время |
| «LSN контрольной точки / REDO» | позиция последней контрольной точки и точки начала REDO в WAL |
| «Текущий LSN WAL» | текущая позиция записи WAL (на ведущем) |
| «LSN воспроизведения» | позиция последнего воспроизведённого WAL (на реплике, вместо предыдущего поля) |
| «Идентификаторы транзакций» | сколько идентификаторов транзакций использовано (следующий XID минус самый старый, по модулю 2³²) и доля от предела 2 147 483 647; при наведении — самый старый и следующий XID |
| «Очередь уведомлений» | заполненность очереди LISTEN/NOTIFY в процентах |
| «Конфигурация перечитана» | сколько времени прошло с последнего перечитывания конфигурации до момента отчёта |
| «Каталог данных» | значение `data_directory`; «—», если параметр недоступен роли мониторинга |
| «Собрано» | версия pgmetrics, которым собран отчёт, например «pgmetrics 1.19.1»; пометка «(локально)» — pgmetrics работал на хосте базы данных. В отчётах без сведений о версии pgmetrics показывается «pgmetrics (схема отчёта 1.x)» — это версия формата отчёта, а не самого pgmetrics |

Признаки, на которые стоит обратить внимание: давняя последняя контрольная точка при активной записи (проверьте `checkpoint_timeout` и страницу [WAL](server.md#wal)), высокая доля использованных идентификаторов транзакций (см. [Очистка (vacuum)](server.md#vacuum)), ненулевая заполненность очереди уведомлений (какой-то слушатель не забирает уведомления).

### Активные оповещения {#overview-alerts}

Карточка «Активные оповещения» показывает до 20 сработавших оповещений: значок уровня, текст правила, объект и текущее значение. Кнопка «Управление» открывает страницу правил (см. [Правила оповещений](alerts.md)). Если ничего не сработало — «Нет сработавших оповещений».

Карточка и счётчик «Оповещения» всегда показывают текущее состояние оповещений, даже если в верхней панели выбран прошлый отчёт.

### Графики активности {#overview-charts}

Раздел «Активность» содержит графики за выбранный в верхней панели период (как устроены графики — см. [Графики](ui.md#charts)).

| График | Ряды | Что показывает |
|---|---|---|
| «Транзакции» | «Фиксации», «Откаты» | число фиксаций и откатов в секунду по всем базам; всплеск откатов обычно означает ошибки в приложении |
| «Бэкенды» | «Всего», «Активные», «Простой в транзакции», «Ждут блокировок» | число клиентских подключений по состояниям; рост «Ждут блокировок» — повод открыть [Блокировки](activity.md#locks) |
| «Строки» | «Выбрано», «Вставлено», «Обновлено», «Удалено» | строки в секунду по всем базам (`tup_fetched`, `tup_inserted`, `tup_updated`, `tup_deleted`) |
| «Попадания в кеш» | «Доля попаданий» | доля попаданий в `shared_buffers` за каждый интервал между отчётами |
| «Генерация WAL» | «WAL» | байты WAL в секунду по изменению позиции WAL; на реплике — скорость воспроизведения. Отчёт без текущей позиции WAL точки не добавляет |
| «Общий размер баз данных» | «Размер» | суммарный размер всех баз |
| «Запись временных файлов» | «Временные файлы» | байты в секунду, записанные во временные файлы; устойчиво высокое значение — сортировки и хеши не помещаются в `work_mem` |
| «Диапазон идентификаторов транзакций» | «Используемые XID» | разница между следующим и самым старым XID (по модулю 2³²); в норме график «пилообразный» — заморозка регулярно его снижает; непрерывный рост без спадов означает, что заморозка не успевает |
| «Средняя нагрузка» | «Нагрузка (1 мин)» | load average хоста; только при наличии системных метрик |
| «Память» | «Занято», «Кеш», «Буферы», «Свободно» | использование памяти хоста; только при наличии системных метрик |

Системные метрики (нагрузка, память, имя хоста) pgmetrics собирает, только когда работает на том же хосте Linux, что и PostgreSQL.

## Диагностика {#diagnostics}

«Диагностика» (адрес `#/s/<id>/diagnostics`) автоматически проверяет отчёт сервера и показывает найденные проблемы и рекомендации по настройкам. Это быстрый способ понять, что на сервере не так, не перебирая все страницы.

### Как формируется результат {#diagnostics-how}

- При открытии страницы сервер pgscope анализирует показываемый отчёт — последний или выбранный в верхней панели. В заголовке указано время проверенного отчёта: «Автоматические проверки отчёта от …».
- Проверки выполняются заново при каждом открытии и обновлении страницы (пока показывается последний отчёт — и автоматически раз в минуту); результаты нигде не сохраняются и не рассылаются. Чтобы получать уведомления о проблемах, настройте [правила оповещений](alerts.md).
- Тексты проблем и рекомендаций формируются на языке интерфейса.
- Многие проверки опираются на накопительные счётчики PostgreSQL, которые растут с момента последнего сброса статистики: неиспользуемые индексы, взаимоблокировки, доля попаданий в кеш, доля откатов, временные файлы. Сразу после сброса статистики такие проверки ничего не находят, а при давно не сбрасывавшейся статистике могут показывать старые проблемы.
- Те же результаты передаются в [AI-чат](#ai-chat) как часть контекста.

### Вкладка «Проблемы» {#issues}

Над вкладками — три счётчика: «Критично», «Предупреждения», «Советы». Ниже — карточки найденных проблем, отсортированные по уровню: сначала критичные, затем предупреждения, затем советы.

| Уровень | Цвет полосы и значка | Смысл |
|---|---|---|
| критично | красный | угроза доступности или сохранности данных: действовать немедленно |
| предупреждение | жёлтый | проблема производительности или надёжности: разобраться в ближайшее время |
| совет | синий | рекомендация, которая улучшит работу или упростит сопровождение |

Карточка проблемы содержит:

- заголовок и метку категории;
- число затронутых объектов;
- объяснение: в чём проблема и что сделать;
- кнопку «Подробнее» / «Скрыть» со списком объектов (баз, таблиц, индексов, бэкендов, слотов); у критичных проблем список раскрыт сразу; в списке не больше 50 строк, остальные сводятся в строку «… и ещё N»;
- кнопку «Открыть», ведущую на страницу сервера, где проблему удобно разбирать.

Если проблем нет, показывается «Проблем не найдено» и «Сервер в порядке.».

### Что проверяется {#issue-checks}

| Категория | Что проверяется | Возможные уровни |
|---|---|---|
| «Очистка» | близость баз к переполнению счётчика транзакций (wraparound), высокий возраст XID, скорый запуск autovacuum против переполнения | критично, предупреждение, совет |
| «Репликация» | неактивные слоты, отставание реплик, реплика не успевает воспроизводить WAL, приостановленное воспроизведение, ошибки подписок логической репликации | предупреждение |
| «WAL» | сбой архивации, очередь файлов на архивацию, слишком много файлов в `pg_wal`, слишком частые контрольные точки | критично, предупреждение |
| «Бэкенды» | число подключений близко к `max_connections`, долгие транзакции, бездействие в транзакции, заполнение очереди уведомлений | критично, предупреждение |
| «Блокировки» | бэкенды ждут блокировок, взаимоблокировки по счётчику и в журнале | предупреждение, совет |
| «Базы данных» | ошибки контрольных сумм, низкая доля попаданий в кеш, много откатов, активное использование временных файлов | критично, предупреждение, совет |
| «Таблицы» | раздувание, много мёртвых строк, таблицы без очистки и анализа, большие таблицы с последовательным сканированием, таблицы без первичного ключа или уникального индекса | предупреждение, совет |
| «Индексы» | неиспользуемые, дублирующиеся и раздутые индексы | предупреждение |
| «Расширения», «Объекты» | доступные обновления расширений, отключённые триггеры | совет |
| «Диск» | заполнение диска с табличным пространством | критично, предупреждение |
| «Сервер» | версия PostgreSQL, которая больше не получает исправлений | предупреждение |
| «Безопасность» | дополнительные роли суперпользователя с правом входа | совет |
| «Запросы» | отсутствие статистики `pg_stat_statements` | совет |

Полный перечень проверок с порогами и рекомендациями — в [Справочнике проверок](checks.md).

### Вкладка «Проверка конфигурации» {#config-check}

Вкладка сопоставляет параметры PostgreSQL из отчёта с распространёнными рекомендациями. Рекомендации сгруппированы в четыре карточки:

| Карточка | Примеры проверяемых параметров |
|---|---|
| «Безопасность» | `ssl`, `password_encryption`, `listen_addresses`, `log_connections`, `log_disconnections`, `row_security` |
| «Сохранность данных» | `fsync`, `full_page_writes`, `synchronous_commit`, `data_checksums`, `wal_level`, `archive_mode` |
| «Производительность» | `shared_buffers`, `effective_cache_size`, `work_mem`, `maintenance_work_mem`, `random_page_cost`, `checkpoint_completion_target`, `track_io_timing`, `effective_io_concurrency`, `max_connections`, `shared_preload_libraries` |
| «Надёжность» | `autovacuum`, `track_counts`, `log_min_duration_statement`, `idle_in_transaction_session_timeout`, `log_checkpoints`, `log_lock_waits`, `log_autovacuum_min_duration`, `hot_standby_feedback`, `max_slot_wal_keep_size` |

В заголовке карточки — число рекомендаций или «Рекомендаций нет» с отметкой «Всё в порядке». Каждая рекомендация содержит уровень («Критично», «Предупреждение» или «Инфо»), имя параметра с текущим значением и совет. Рекомендация выводится, только если параметр есть в отчёте.

Рекомендации — эвристики общего назначения. Например, совет снизить `random_page_cost` до 1.1 рассчитан на SSD, а совет про `shared_buffers` — на выделенный под PostgreSQL сервер. Оценивайте их применительно к своему оборудованию и нагрузке. Та же проверка доступна на вкладке «Проверка конфигурации» страницы [Конфигурация](server.md#config).

### Диагностика и оповещения {#diagnostics-vs-alerts}

| | Диагностика | Правила оповещений |
|---|---|---|
| Что проверяется | фиксированный набор проверок pgscope | метрики и пороги, которые вы задаёте сами |
| Когда | при открытии страницы, по показываемому отчёту | при каждом новом отчёте |
| Уведомления | нет | да, по настроенным каналам |
| Где видно | страница «Диагностика», контекст AI-чата | значок на карточке сервера, «Обзор», страница «Оповещения» |

Удобный порядок работы: используйте диагностику для периодического разбора сервера, а для ситуаций, о которых нужно узнавать сразу (заполнение диска, отставание реплики, возраст XID), заведите [правила оповещений](alerts.md).

## AI-чат {#ai-chat}

«AI-чат» (адрес `#/s/<id>/chat`, кнопка с роботом в верхней панели) отвечает на вопросы о сервере на естественном языке, опираясь на данные последнего отчёта.

> [!WARNING]
> AI-чат отправляет данные о сервере во внешний облачный сервис: вопросы и сжатая выжимка отчёта уходят в Anthropic API. Без ключа `PGSCOPE_AI_KEY` чат выключен и никуда ничего не отправляет. Для закрытого контура см. [Закрытый контур](#ai-air-gapped).

### Включение {#ai-setup}

Чат настраивается переменными окружения процесса pgscope (подробнее — [Настройка pgscope](config.md#ai)):

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PGSCOPE_AI_KEY` | — | API-ключ Anthropic; без него чат выключен |
| `PGSCOPE_AI_MODEL` | `claude-opus-5-5` | модель, которой отправляются вопросы |
| `PGSCOPE_AI_BASE_URL` | — | другой адрес Anthropic API, например корпоративный прокси или шлюз |

Других провайдеров нет: чат всегда работает через Anthropic API. Переменная `PGSCOPE_AI_PROVIDER` из прежних версий больше не читается, её можно удалить из настроек.

Переменные читаются только при запуске, поэтому после изменения pgscope нужно перезапустить:

```bash
PGSCOPE_AI_KEY=ваш-ключ-anthropic \
PGSCOPE_DB=postgres://pgscope@dbhost/pgscope \
PGSCOPE_BASE_URL=http://monitor:8080 \
./pgscope
```

Если ключ не задан, на странице чата показывается «AI-чат не настроен. Задайте PGSCOPE_AI_KEY (API-ключ Anthropic) и перезапустите pgscope.», а поле ввода и готовые вопросы недоступны.

### Работа с чатом {#ai-usage}

- Пока диалог пуст, страница предлагает готовые вопросы: «Кратко оцени состояние этого сервера.», «Какие запросы оптимизировать в первую очередь и как?», «Какие индексы стоит удалить или добавить?», «Справляется ли autovacuum? Есть ли риск переполнения счётчика транзакций?», «Проверь конфигурацию под текущую нагрузку.». Щелчок по такому вопросу сразу отправляет его.
- Enter отправляет вопрос, Shift+Enter переносит строку. Пока модель отвечает, показывается «Думаю…»; ответ приходит целиком, без постепенного вывода.
- Ответ оформляется: заголовки, списки, полужирный текст, код и блоки SQL.
- Модель отвечает на языке интерфейса; если задать вопрос на другом языке, ответ будет на языке вопроса.
- Ответ всегда строится по **последнему** отчёту сервера, даже если в верхней панели выбран прошлый отчёт.
- Переписка хранится только в текущей вкладке браузера, отдельно для каждого сервера: она переживает перезагрузку страницы, но исчезает при закрытии вкладки. На сервере pgscope переписка не сохраняется, другим пользователям не видна. Кнопка «Новый диалог» очищает её.
- С каждым вопросом отправляется вся история диалога. В одном диалоге может быть не больше 50 сообщений, то есть не больше 25 вопросов; дальше начните «Новый диалог».
- Чатом может пользоваться любой пользователь с доступом к серверу.

Ответы модели могут содержать ошибки. Проверяйте предложенные SQL-команды и изменения конфигурации, прежде чем применять их на рабочем сервере.

### Какие данные уходят в модель {#ai-context}

С каждым вопросом pgscope отправляет в Anthropic API инструкцию для модели (системный промпт), историю диалога и сжатую выжимку последнего отчёта в формате JSON:

| Раздел выжимки | Содержимое |
|---|---|
| сведения о сервере | имя сервера в pgscope, время сбора отчёта, полная версия PostgreSQL, время запуска, режим восстановления, системный идентификатор, линия времени |
| WAL и фоновые процессы | число файлов WAL и готовых к архивации, статистика архивации, bgwriter, checkpointer и WAL |
| хост и хранение | системные метрики (если есть, включая имя хоста), табличные пространства, базы данных |
| репликация | исходящая и входящая репликация, слоты |
| активность | число процессов по типам, общее число бэкендов, до 60 бэкендов в любом состоянии, кроме `idle` (бэкенды без состояния тоже не передаются), с текстами их запросов, невыданные блокировки и цепочки блокирующих PID |
| анализ | результаты [диагностики](#diagnostics) и [проверки конфигурации](#config-check) |
| объекты | расширения, роли, ход текущих операций VACUUM, 40 самых больших таблиц и 40 самых больших индексов |
| настройки | все параметры, значения которых отличаются от значений по умолчанию |
| запросы | 25 запросов с наибольшим общим временем из `pg_stat_statements`: текст, база, пользователь, вызовы, общее, среднее и максимальное время, строки, блоки |
| облако | метрики AWS RDS, если они есть в отчёте |

Выжимка строится заново при каждом вопросе из последнего на этот момент отчёта. Системный промпт вместе с выжимкой помечается для кеширования на стороне Anthropic: пока не пришёл новый отчёт, выжимка не меняется, и следующие вопросы обрабатываются дешевле. После прихода нового отчёта выжимка другая, и кеш не используется.

> [!WARNING]
> Тексты запросов из `pg_stat_activity` содержат фактические значения параметров, а тексты из `pg_stat_statements` могут содержать литералы. Вместе с именами баз, таблиц, ролей и хоста они покидают ваш периметр. Оцените это с точки зрения требований к данным до включения чата.

### Ограничения и ошибки {#ai-errors}

| Сообщение | Код HTTP | Причина и что делать |
|---|---|---|
| «AI-чат не настроен: укажите API-ключ Anthropic в PGSCOPE_AI_KEY» | 501 | ключ не задан; задайте `PGSCOPE_AI_KEY` и перезапустите pgscope |
| «Некорректный запрос» | 400 | в диалоге больше 50 сообщений или запрос повреждён; начните «Новый диалог» |
| «Отчётов пока нет» | 404 | от сервера ещё не пришёл ни один отчёт |
| «AI-провайдер вернул HTTP N» | 502 | Anthropic API ответил ошибкой: например, 401 — неверный ключ, 429 — превышен лимит запросов, 5xx — сбой на стороне провайдера |
| «Не удалось связаться с AI-провайдером» | 502 | нет сетевого доступа к API: проверьте выход в интернет или прокси, DNS и значение `PGSCOPE_AI_BASE_URL`; подробности — в журнале pgscope |
| «AI-модель отказалась отвечать на этот вопрос» | 502 | модель отклонила вопрос; переформулируйте его |
| «(ответ обрезан)» в конце ответа | — | ответ упёрся в предел длины (16 000 токенов); задайте более узкий вопрос |

При ошибке вопрос возвращается в поле ввода, а диалог остаётся прежним — после устранения причины его можно отправить ещё раз.

### Закрытый контур {#ai-air-gapped}

pgscope рассчитан на работу без доступа в интернет. Выход наружу нужен только AI-чату и уведомлениям в облачные сервисы (Slack, PagerDuty, VictorOps, xMatters — см. [Каналы уведомлений](notifications.md)). Для AI-чата в закрытом контуре:

- **Оставьте `PGSCOPE_AI_KEY` пустым.** Чат будет выключен и не будет обращаться наружу; остальные страницы интерфейса работают полностью автономно.
- **`PGSCOPE_AI_BASE_URL`** позволяет направить запросы через корпоративный прокси или шлюз, но данные всё равно уходят в Anthropic API.
- **Локальные модели штатно не поддерживаются:** запрос использует специфичные для Anthropic параметры API, работа через совместимые шлюзы к локальным моделям не проверялась.
- **Альтернатива внутри контура** — [диагностика](#diagnostics) и [проверка конфигурации](#config-check): это тот же анализ, который получает модель, и он выполняется целиком на сервере pgscope.
