# Быстрый старт

Кратчайший путь от нуля до графиков: запустить pgscope, зарегистрироваться, подготовить роль мониторинга, отправить первый отчёт и поставить отправку по расписанию. Займёт около 15 минут. Подробности каждого шага — на страницах, на которые ведут ссылки.

## Что понадобится {#prerequisites}

- Linux-хост для pgscope с Docker и Docker Compose — или Go и Node.js для сборки бинарного файла и любой доступный сервер PostgreSQL для хранения данных (требования к версиям — в разделе [Требования](install.md#requirements)).
- Наблюдаемый сервер PostgreSQL, на котором вы можете создать роль.
- Утилиты [pgmetrics](https://pgmetrics.io) и [pgdash CLI](https://github.com/rapidloop/pgdash) на хосте, откуда будут отправляться отчёты. Лучше всего — на хосте самой базы данных: только так собираются системные метрики и данные из журнала PostgreSQL.
- Сетевой доступ с этого хоста к pgscope по HTTP(S) и от pgmetrics к PostgreSQL.

> [!TIP]
> Если базы работают в контейнерах Docker или Docker Swarm, вместо шагов 4–7 используйте pgscope-agent: он сам находит контейнеры и отправляет отчёты. См. [Docker и Docker Swarm](docker.md).

## Шаг 1. Запустите pgscope {#start}

Выберите один из двух вариантов.

### Вариант А: Docker Compose {#start-compose}

В репозитории есть готовый `deploy/docker-compose.yml`: он запускает pgscope и базу для хранения `postgres:17-alpine` с данными в томе `pgscope-data`. Выполните в каталоге с исходниками pgscope:

```bash
docker build -t pgscope:latest .
cd deploy
printf 'PGSCOPE_DB_PASSWORD=%s\nPGSCOPE_BASE_URL=%s\n' 'надёжный-пароль' 'http://monitor.example.com:8080' > .env
docker compose up -d
docker compose logs pgscope
```

- `PGSCOPE_DB_PASSWORD` — пароль пользователя `pgscope` в базе для хранения, обязателен.
- `PGSCOPE_BASE_URL` — адрес, по которому pgscope будут открывать браузеры и pgdash CLI. Он подставляется в готовые команды в интерфейсе и в ссылки в оповещениях.
- Порт на хосте — 8080; другой задаётся в `.env` переменной `PGSCOPE_PORT`.

В логе должна появиться строка вида `pgscope listening on :8080 (public URL http://monitor.example.com:8080)`.

### Вариант Б: бинарный файл и существующий PostgreSQL {#start-binary}

Соберите pgscope (нужны Go и Node.js, см. [Сборка из исходников](install.md#build)):

```bash
cd web && npm ci && npm run build && cd .. && go build -o pgscope .
```

Создайте роль и базу для хранения на любом доступном сервере PostgreSQL:

```bash
sudo -u postgres createuser --pwprompt pgscope
sudo -u postgres createdb -O pgscope pgscope
```

Запустите pgscope. Таблицы он создаст сам при первом запуске. Пароль удобнее передать переменной `PGPASSWORD`: тогда спецсимволы в нём не нужно кодировать для URL.

```bash
PGSCOPE_DB='postgres://pgscope@dbhost:5432/pgscope' \
PGPASSWORD='надёжный-пароль' \
PGSCOPE_BASE_URL='http://monitor.example.com:8080' \
./pgscope
```

Для постоянной работы оформите pgscope как сервис systemd и поставьте перед ним HTTPS-прокси: [Установка и обновление](install.md).

## Шаг 2. Зарегистрируйтесь {#signup}

1. Откройте в браузере адрес pgscope, например `http://monitor.example.com:8080`.
2. На странице входа нажмите «Регистрация».
3. Укажите email и пароль и нажмите «Зарегистрироваться». Пароль — не короче 8 символов и не длиннее 72 байт в UTF-8: латинская буква занимает один байт, кириллическая — два.

Вы сразу окажетесь в системе. Сессия действует 30 дней.

> [!WARNING]
> По умолчанию (`PGSCOPE_SIGNUP=first`) зарегистрироваться может только первый пользователь: он становится владельцем, а ссылка «Регистрация» после этого пропадает. Зарегистрируйтесь сразу после запуска, пока адрес pgscope не открыли другие. Коллегам открывайте доступ приглашениями (см. [Приглашение по email](teams.md#invite)); другие режимы описаны в разделе [PGSCOPE_SIGNUP](config.md#pgscope-signup).

## Шаг 3. Скопируйте API-ключ {#api-key}

Откройте «Профиль» — ссылку с вашим email внизу бокового меню. В карточке «API-ключ» нажмите кнопку копирования рядом с ключом. Ключом подписываются отчёты: все серверы, отправленные с ним, принадлежат вашему аккаунту.

Там же, в карточке «Отправка отчётов», есть готовые команды с уже подставленными ключом и адресом. Пока серверов нет, такая же команда показана и на странице «Серверы».

## Шаг 4. Подготовьте роль мониторинга {#monitoring-role}

На наблюдаемом сервере PostgreSQL создайте роль с правами только на чтение статистики:

```sql
CREATE ROLE pgmon LOGIN PASSWORD 'надёжный-пароль';
GRANT pg_monitor TO pgmon;
```

Разрешите этой роли подключение в `pg_hba.conf` с хоста, где будет работать pgmetrics, и сохраните пароль в `~/.pgpass` пользователя, от имени которого будет выполняться сбор:

```bash
echo 'dbhost:5432:*:pgmon:надёжный-пароль' >> ~/.pgpass
chmod 600 ~/.pgpass
```

Чтобы заработала страница «Запросы», установите расширение `pg_stat_statements`; для планов выполнения нужен `auto_explain`. Это можно сделать позже: см. [Подготовка PostgreSQL](postgres.md).

## Шаг 5. Отправьте первый отчёт {#first-report}

Установите pgmetrics и pgdash CLI (готовые сборки — на страницах проектов, pgmetrics с исправлениями pgscope — см. [pgmetrics из сборки pgscope](collect.md#pgmetrics-build); для закрытого контура см. [Установка в закрытом контуре](install.md#air-gapped)). Затем выполните, подставив свои значения:

```bash
pgmetrics --no-password -f json -h dbhost -U pgmon db1 db2 \
  | pgdash -a ВАШ_API_КЛЮЧ --base-url=http://monitor.example.com:8080/api/v1 report prod-db-1
```

- `db1 db2` — базы, которые нужно видеть в pgscope; чтобы собрать все пользовательские базы, укажите `--all-dbs`.
- `prod-db-1` — имя сервера в pgscope: от 1 до 64 символов из латинских букв, цифр и `_ . -`. Сервер создаётся автоматически при первом отчёте под новым именем. Удобно использовать имя хоста.
- `--base-url` обязателен и должен заканчиваться на `/api/v1`. Без него pgdash CLI отправит отчёт в облачный pgDash.
- `--no-password` не даёт pgmetrics зависнуть на запросе пароля: пароль берётся из `~/.pgpass`.

Если pgscope отклонил отчёт, расшифровка кодов ответа — в разделе [Ответы сервера](collect.md#responses).

## Шаг 6. Посмотрите данные {#see-data}

Обновите страницу «Серверы» в pgscope: появится карточка `prod-db-1` с версией PostgreSQL и краткой сводкой. Откройте её:

- [«Обзор»](monitoring.md#overview) — основные показатели и графики;
- [«Диагностика»](monitoring.md#diagnostics) — найденные проблемы и проверка конфигурации, работает уже по первому отчёту;
- остальные разделы — в боковом меню сервера.

Графикам нужно несколько отчётов: после первого отчёта видны текущие значения, линии появятся после следующих.

## Шаг 7. Настройте регулярную отправку {#schedule}

Отправляйте отчёт каждые 5 минут, например через cron пользователя, у которого настроен `~/.pgpass`:

```bash
crontab -e
```

```text
*/5 * * * * pgmetrics -w -f json -h dbhost -U pgmon db1 db2 | pgdash -a ВАШ_API_КЛЮЧ --base-url=http://monitor.example.com:8080/api/v1 report prod-db-1
```

pgscope принимает отчёты одного сервера не чаще раза в 60 секунд (`PGSCOPE_MIN_REPORT_INTERVAL`), более частые отклоняются с кодом 429. Не ставьте сбор чаще раза в минуту. Другие способы автоматизации, PgBouncer и Pgpool — на странице [Отправка отчётов](collect.md).

## Если что-то не так {#problems}

| Симптом | Что проверить |
|---|---|
| Страница pgscope не открывается | `docker compose ps` и `docker compose logs pgscope` (или вывод `./pgscope`); при ошибке `schema setup: …` pgscope не смог подключиться к базе для хранения или создать в ней таблицы |
| На странице входа нет ссылки «Регистрация» | в базе уже есть учётная запись (по умолчанию регистрируется только первый пользователь) или задано `PGSCOPE_SIGNUP=closed`. Попросите владельца пригласить вас или см. [PGSCOPE_SIGNUP](config.md#pgscope-signup) |
| После входа снова показывается страница входа | `PGSCOPE_BASE_URL` начинается с `https://`, а вы открыли pgscope по `http://`: браузер не сохраняет защищённую cookie. Откройте pgscope по HTTPS или исправьте адрес (см. [Cookie сессии и флаг Secure](install.md#secure-cookie)) |
| Сервер не появился после отправки | код ответа pgscope ([Ответы сервера](collect.md#responses)), адрес с `/api/v1`, ключ из профиля этого же pgscope |
| Ответ 429 | отчёты одного сервера приходят чаще, чем раз в 60 секунд |
| Ответ 413 | отчёт больше предела `PGSCOPE_MAX_REPORT_MB` (по умолчанию 256 МиБ) или предела размера тела на обратном прокси, см. [PGSCOPE_MAX_REPORT_MB](config.md#pgscope-max-report-mb) |
| Пустая страница «Запросы» | не установлен или недоступен `pg_stat_statements`, см. [Подготовка PostgreSQL](postgres.md) |

Остальные случаи — в разделе [Решение проблем и FAQ](troubleshooting.md).
